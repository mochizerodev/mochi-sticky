Goal: Capture telemetry around build/release pipeline runs so multi-platform regressions surface quickly.

Scope:
- Log durations/results per platform (Linux/Windows/macOS), including build/test/export steps, in a consistent format.
- Emit telemetry when GitHub Actions jobs start/finish, capturing config used, branch/tag, and artifact sizes.
- Provide hooks for CLI/TUI to display recent release telemetry (success rate, slowest step) in dashboards.

Acceptance:
- Build/release commands record structured logs for each platform and pipeline stage.
- CLI/TUI can read the logs and summarize timings/failures in a brief report.
- Documentation explains where logs live and how to interpret them (e.g., linking to CI artifacts).

## Done Summary (2026-02-10)
- Added `internal/release` telemetry domain with schema, validation, storage, and summary aggregation (success rate + slowest stage).
- Added CLI commands:
  - `mochi-sticky release telemetry` (human + JSON summary output)
  - `mochi-sticky release telemetry import <file...>` (import telemetry JSON into local storage)
- Added tests:
  - `internal/release` unit tests for decode/store/summarize behavior
  - `cmd/integration/release` integration test covering import + summary output
- Updated `.github/workflows/release.yml` to emit structured telemetry JSON for build/smoke jobs, including stage durations, run metadata, and artifact sizes.
- Added telemetry artifact uploads in CI and included build telemetry files in release assets upload.
- Updated docs with telemetry location and usage:
  - `README.md` CLI command list
  - `.sticky/wiki/release/distribution.md` telemetry interpretation section
