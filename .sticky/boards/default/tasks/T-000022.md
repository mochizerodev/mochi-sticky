Goal: Provide a reliable installer path for Linux, macOS, and Windows so users can install, verify, upgrade, and remove `mochi-sticky` without manual setup friction.

Platform Usage

Linux:
- Primary path: shell installer (`curl|bash`) that installs into `/usr/local/bin` or user-local bin when non-root.
- Verify: `mochi-sticky --version` and `mochi-sticky init`.
- Upgrade: rerun installer with latest version flag (or `latest`).
- Uninstall: remove binary + optional shell completion/config artifacts documented in install guide.

macOS:
- Primary path: Homebrew tap (`brew tap ...` + `brew install mochi-sticky`) and optional direct binary install.
- Verify: `mochi-sticky --version` and a basic MCP smoke check (`echo ... | mochi-sticky mcp`).
- Upgrade: `brew update && brew upgrade mochi-sticky` (or reinstall script path).
- Uninstall: `brew uninstall mochi-sticky` and cleanup of optional config/cache files.

Windows:
- Primary path: signed `.zip`/`.exe` release artifact with checksum verification and PATH setup instructions.
- Verify: `mochi-sticky --version` in PowerShell and basic command execution (`mochi-sticky board list`).
- Upgrade: install newer artifact in-place with versioned backup/replace behavior.
- Uninstall: remove executable and any optional user data paths documented for PowerShell users.

Scope:
- Define packaging/distribution for each platform and automate artifact publishing in release workflow.
- Publish checksums/signature metadata and include install commands in release notes.
- Add installation docs for fresh install, upgrade, downgrade, and uninstall per platform.
- Add CI smoke tests that validate install + version check on Linux/macOS/Windows runners.
- Document failure handling for PATH issues, permission errors, and checksum mismatches.

Acceptance:
- Release produces downloadable install artifacts and checksums for Linux, macOS, and Windows.
- Fresh machine validation succeeds on each platform: install, `mochi-sticky --version`, and one basic command.
- Upgrade and uninstall steps are documented and tested at least once per platform.
- Release notes include install snippets and troubleshooting references.

Archive Criteria (when this task can be archived):
- Installers/artifacts are live for all supported platforms in at least one published release.
- Platform docs exist and match actual installer behavior (verified with manual or CI smoke runs).
- Upgrade and uninstall paths are validated and documented.
