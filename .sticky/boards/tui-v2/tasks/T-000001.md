Goal: Introduce top-level tabs to separate primary features and remove context confusion.

Implemented (2026-02-15):
- Added a global app-tab model (`Boards`, `Wiki`, `ADRs`) and wired global `Ctrl+1/2/3` switching in the TUI event handler.
- Added per-tab screen memory so switching tabs preserves the last focused screen/state for each area (for example, returning to Boards restores the prior board/task view).
- Updated tab transitions to reuse cached Wiki/ADR state when available, while still loading data on first entry.
- Added a persistent top tab bar to the shell header and a consistent footer status line across screens (includes active tab, loading state, and terminal size).
- Updated help text to advertise global tab shortcuts.
- Kept existing board/wiki/adr workflows and modal/action screens functional.

- `go test ./...`

Outcome:
- Tabs switch instantly via `Ctrl+1/2/3`.
- Per-tab focus/selection state is preserved when switching.
- Existing Boards/Wiki/ADR actions continue to work with the new shell navigation.

Re-implemented (2026-02-17):
- Updated Boards home behavior to match the latest TUI v2 board mockup: board-list focus now drives a board info preview pane, and `Enter` remains the explicit open/use action for loading that board's tasks.
- Added background board-preview loading for the currently highlighted board (counts + context + last activity summary), including refresh on list navigation and board-state updates.
- Updated responsive board rendering so `>=120` and `90..119` use list + preview center panes when board focus is active, and `<90` falls back to single-pane board list view.
- Aligned board-list focus/key behavior with responsive breakpoints so board navigation works consistently at `>=90` and in narrow list mode.
